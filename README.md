# RouteMind

**자연어로 요청하는 배송 최적화 어시스턴트** (포트폴리오, 진행 중)

"내일 강남·서초 냉장 배송 80건, 1톤 트럭 5대"처럼 요청하면, LLM이 요청을 해석하고 RAG가 관련 운영 규정을 찾아 제약조건으로 바꾸며, 최적화 엔진이 거점과 경로를 계산해 지도와 요약으로 보여주는 것이 목표입니다. 숫자를 만드는 계산은 모두 최적화 엔진이 맡고, LLM은 요청 해석과 결과 설명만 합니다.

> **현재 단계: 0단계 (준비와 데이터)** · 문제 정의서 초안과 가상 데이터 생성기까지 완료

## 빠른 시작

[uv](https://docs.astral.sh/uv/)가 설치되어 있으면 저장소 루트에서 명령 한 줄로 데이터가 만들어집니다.

```bash
uv run python -m data.generate
```

## 문제 정의서 (초안)

### 상황

서울 전역의 고객 500곳에 하루 동안 상온·냉장 상품을 배송하는 택배·유통 회사를 가정합니다. 회사는 후보지 10곳 중 몇 곳에 허브를 열지 정하고, 열린 허브에서 차량을 출발시켜 고객에게 배송합니다. 결정은 시간 단위가 다른 두 단계로 나눕니다.

|           | 1단계: 거점 입지                               | 2단계: 배송 경로                          |
| --------- | ---------------------------------------------- | ----------------------------------------- |
| 질문      | 어느 허브를 열고, 고객을 어느 허브에 배정할까? | 각 허브에서 어떤 차량이 어떤 순서로 돌까? |
| 결정 주기 | 전략적 (몇 달~몇 년)                           | 운영적 (매일)                             |
| 모델      | 용량제약 시설입지 문제 (CFLP)                  | 시간창·용량 제약 차량경로 문제 (VRPTW)    |
| 풀이      | MIP (PuLP + HiGHS)                             | 휴리스틱 직접 구현 → OR-Tools와 비교      |

두 문제를 한 번에 푸는 위치-경로 문제(LRP)는 훨씬 어렵기 때문에, 실무처럼 **입지를 먼저 정하고 그 결과 위에서 경로를 푸는 분해 방식**을 씁니다. 이 분해로 잃는 것(입지 단계는 경로 비용을 직선 수송비로 근사함)은 1·2단계를 마친 뒤 한계로 정리합니다.

### 1단계 · 거점 입지 (CFLP)

**집합과 파라미터**

| 기호        | 의미                        | 데이터                      |
| ----------- | --------------------------- | --------------------------- |
| $I$         | 고객 집합                   | `customers.csv`             |
| $J$         | 후보 허브 집합              | `hubs.csv`                  |
| $f_j$       | 허브 $j$ 고정비 (원/일)     | `fixed_cost_krw`            |
| $Q_j$       | 허브 $j$ 처리 용량 (kg/일)  | `capacity_kg`               |
| $d_i$       | 고객 $i$ 수요 (kg)          | `demand_kg`                 |
| $\ell_{ij}$ | 허브 $j$–고객 $i$ 거리 (km) | `distance_km.csv`           |
| $\alpha$    | 수송 단가 (원/kg·km)        | 1단계에서 시나리오로 정함   |
| $J^{cold}$  | 냉장 설비가 있는 허브       | `has_cold == True`          |
| $I^{cold}$  | 냉장 상품 고객              | `product_type == "chilled"` |

**결정변수**

- $y_j \in \lbrace 0,1 \rbrace$: 허브 $j$를 열면 1
- $x_{ij} \in \lbrace 0,1 \rbrace$: 고객 $i$를 허브 $j$에 배정하면 1 (한 고객은 한 허브에서만 받는 단일 소싱)

**목적함수**: 허브 고정비 + 수송비 최소화

$$
\min \sum_{j \in J} f_j\, y_j + \sum_{i \in I}\sum_{j \in J} \alpha\, d_i\, \ell_{ij}\, x_{ij}
$$

**제약**

$$
\begin{aligned}
&\textstyle\sum_{j \in J} x_{ij} = 1 && \forall i \in I &&\text{(모든 고객은 정확히 한 허브에 배정)}\\
&\textstyle\sum_{i \in I} d_i\, x_{ij} \le Q_j\, y_j && \forall j \in J &&\text{(열린 허브만, 용량 이내로)}\\
&x_{ij} \le y_j && \forall i, j &&\text{(위 제약에 포함되지만 선형완화를 강하게 만듦)}\\
&x_{ij} = 0 && \forall i \in I^{cold},\ j \notin J^{cold} &&\text{(냉장 상품은 냉장 허브에서만)}
\end{aligned}
$$

> 1단계에서 확인할 것: $x_{ij} \le y_j$를 빼고 풀면 LP 완화값과 풀이 시간이 어떻게 달라지는가?

### 2단계 · 배송 경로 (VRPTW)

허브 하나와 거기 배정된 고객들에 대해 풉니다.

**파라미터 (추가)**

| 기호              | 의미                                       | 데이터                                             |
| ----------------- | ------------------------------------------ | -------------------------------------------------- |
| $K$               | 사용 가능한 차량                           | `vehicle_types.csv` (`count`만큼)                  |
| $C_k,\ F_k,\ c_k$ | 차량 $k$의 용량, 일 고정비, km당 비용      | `capacity_kg`, `fixed_cost_krw`, `cost_per_km_krw` |
| $[a_i, b_i]$      | 고객 $i$의 도착 가능 시간창                | `tw_start_min`, `tw_end_min`                       |
| $s_i$             | 하역 시간 (분)                             | `service_min`                                      |
| $\tau_{ij}$       | 이동 시간 = $\ell_{ij}$ / 평균 속도 25km/h | `metadata.json`                                    |
| $T$               | 기사 최대 근무 시간 600분                  | `metadata.json`                                    |

**결정변수**

- $x_{ijk} \in \lbrace 0,1 \rbrace$: 차량 $k$가 $i$에서 $j$로 바로 이동하면 1
- $u_k \in \lbrace 0,1 \rbrace$: 차량 $k$를 쓰면 1
- $t_{ik} \ge 0$: 차량 $k$가 고객 $i$에서 하역을 시작하는 시각

**목적함수**: 차량 고정비 + 주행 비용 최소화

$$
\min \sum_{k \in K} F_k\, u_k + \sum_{k \in K}\sum_{i}\sum_{j} c_k\, \ell_{ij}\, x_{ijk}
$$

**제약 (말로 정리, 수식은 2단계에서 다듬기)**

1. 모든 고객은 정확히 한 번, 한 차량이 방문한다 (분할 배송 없음).
2. 차량은 허브에서 출발해 허브로 돌아오고, 들어온 차는 반드시 나간다 (흐름 보존).
3. 한 차량에 실은 수요 합은 용량 $C_k$ 이하.
4. 시간창: $a_i \le t_{ik} \le b_i$. 일찍 도착하면 기다릴 수 있다. 순서 연결은 Big-M으로
   $t_{jk} \ge t_{ik} + s_i + \tau_{ij} - M(1 - x_{ijk})$
5. 근무 시간: 출발부터 복귀까지 $T$ 이하.
6. 냉장 고객은 냉장차($k$의 `refrigerated == True`)만 방문할 수 있다.

> 이 수식은 문제를 정확히 정의하려고 쓴 것이고, 고객 수백 곳 규모에서는 MIP로 풀기 어렵습니다. 그래서 2단계에서는 휴리스틱(Nearest Neighbor, 2-opt, Savings, SA, ALNS)으로 풀고, 소형 인스턴스에서 최적해와의 gap을 잽니다.

### 가정

| 가정                               | 현실과의 차이                              | 언제 다시 볼까                      |
| ---------------------------------- | ------------------------------------------ | ----------------------------------- |
| 거리는 하버사인 직선거리           | 도로 거리보다 짧음 (도심은 보통 1.2~1.4배) | 예비 주간에 OSRM으로 교체           |
| 이동 속도는 하루 종일 25km/h       | 출퇴근 시간 정체 무시                      | 3단계 시뮬레이션에서 확률분포로     |
| 수요·하역 시간은 하루 전에 확정    | 실제로는 당일 변동, 부재, 반품             | 3단계                               |
| 냉장차는 상온 상품도 실을 수 있음  | 회사 정책에 따라 다름                      | 4단계 규정집에서 규칙으로           |
| 하루 단위, 허브 간 이동 없음       | 실제로는 간선 수송(허브↔허브) 존재         | 범위 밖으로 명시                    |
| 허브 비용·용량, 차량 비용은 설정값 | 실제 단가가 아님                           | 1단계 시나리오 분석에서 민감도 확인 |
| 고객은 자치구 인구 비례로 분포     | 상업 지역 수요 집중, 한강 위 좌표 가능성   | 0단계 데이터 점검에서 확인          |

## 데이터 명세

`data/generated/`에 생성되며, 엑셀에서 열어도 한글이 깨지지 않도록 UTF-8(BOM) CSV로 저장합니다. 고정 입력값(자치구, 후보 허브, 차량)은 [`data/seoul.py`](data/seoul.py)에 있습니다.

| 파일                | 행       | 주요 열                                                                                                                                                                     |
| ------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `customers.csv`     | 고객 500 | `customer_id`, `district`, `lat`, `lon`, `customer_type`(residential/commercial), `product_type`(ambient/chilled), `demand_kg`, `service_min`, `tw_start_min`, `tw_end_min` |
| `hubs.csv`          | 후보 10  | `hub_id`, `name`, `lat`, `lon`, `fixed_cost_krw`, `capacity_kg`, `has_cold`                                                                                                 |
| `vehicle_types.csv` | 차종 3   | `vehicle_type`, `name`, `capacity_kg`, `refrigerated`, `fixed_cost_krw`, `cost_per_km_krw`, `count`                                                                         |
| `nodes.csv`         | 510      | `node_index`, `node_id`, `node_type` — 허브 10개가 먼저, 고객 500개가 뒤                                                                                                    |
| `distance_km.csv`   | 510×510  | 행·열 이름이 `node_id`인 거리 행렬 (km)                                                                                                                                     |
| `metadata.json`     | —        | 생성 설정(시드 등)과 요약 통계                                                                                                                                              |

생성 규칙:

- **위치**: 자치구를 인구 비례로 뽑고, 구 중심에서 표준편차 1km 정규분포로 흩뿌림 (±2.5km에서 자름)
- **고객 유형**: 상업 30%, 가정 70%
- **상품**: 냉장 25%, 상온 75%
- **수요량**: 로그정규분포, 중앙값 가정 12kg·상업 40kg, 1~200kg로 자름
- **하역 시간**: 가정 3분·상업 8분 + 무게 1kg당 0.05분
- **시간창** (자정부터 분, 운영 08:00~20:00): 가정은 40%가 시간 무관, 60%가 3시간 창 / 상업은 오전 09~12시, 오후 13~17시, 영업시간 09~18시 중 하나
- **생성 직후 점검**: 총수요 ≤ 허브 총용량, 냉장 수요 ≤ 냉장 허브 용량, 고객 1곳 수요 ≤ 최소 차량 용량, 시간창 ≥ 하역 시간. 어기면 파일을 만들지 않고 멈춤

## 저장소 구조

```
routemind/
├── data/            # 0단계: 데이터 생성기, 거리 계산 (생성 결과는 data/generated/, 커밋 안 함)

│   ├── location/    # 1단계: 거점 입지 MIP

└── tests/
```
